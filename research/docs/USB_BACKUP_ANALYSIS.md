## 结论

备份中确实有可恢复的音频：`PADSMPLA.BIN` 包含32条 PCM16 单声道数据，按相邻同名、同长度记录导出16个立体声试听 WAV。另恢复265条 GM Program 原始记录。**尚未发现原机整套 TG 采样 ROM，也未找到已验证的电脑端 ROM 导出命令。**

固件中进一步确认了独立启动 SerialFlash 的只读函数与身份数据读取路径；这是新的研究线索，不能等同于取得 PCM 音频或可用的 USB 读出入口。

## 已导出的 Pad 素材

原 ARM 加载器 `0x287adc` 先读64字节 `KSB0` 头，再循环32条记录。记录为100字节描述符，之后紧接 `descriptor+0x44` 指定长度的音频；读取点为 `0x287c5c`，PCM读取在 `0x287cf4..0x287d30`。按这个结构解析恰好到 EOF，音频总计14376960字节。

32条记录的 flags 均为 `0x12`，pitch 均为0，`end+1` 均等于 `PCM字节数/2`。以 signed little-endian PCM16 保存；WAV 采样率48000Hz依据已有恢复出的 `48000 * 2**(pitch/1536)` 关系。无重采样、归一化或效果处理。每个 WAV 均重新读取并逐声道逐字节与源 PCM 对照。

相邻记录名称及长度完全成对，导出时将前条放左、后条放右；**物理左右顺序尚未确认**。这些是该机器当前的 Pad sampler 内容，不能仅凭名称确定是出厂示范还是用户素材，也不能把它们当作496个 multisample 对应的原机波形库。

## 新确认的启动 Flash 读取路径

以下地址均为 v1.2.4 解压镜像偏移。

| 函数/路径 | 已确认行为 | 边界 |
| --- | --- | --- |
| `0x12ea0c` | 发送三字节地址，检查地址小于 `0x400000` | 4MiB是驱动地址限制，尚不是芯片容量实测 |
| `0x12eec0` | 从指定64KiB块起点读取指定字节数 | 内部函数，未找到主机导出调用 |
| `0x12ef64` | 按64KiB块读取，首块与末块均限制在 `0..0x3f` | 与 TG 的256KiB块读取后端不同 |
| `0x117e64` | 返回启动代码逻辑长度 `0x20000`（128KiB） | 不代表整个 SPI 芯片只有128KiB |
| `0x118000` | 从块 `0x3f` 的起点读32字节身份数据 | 诊断 UUID 显示与 PCM 上下文初始化调用它 |
| `0x17f36c` | 读 `BOOTSYS.BIN`，调用 `0x117e6c` 更新启动代码 | 加载/写入路径，不能作为备份导出教程 |

离线执行了6个原 ARM 读取案例：小段读取、首块与末块完整65536字节、身份数据读取包装。仅 SPI/I/O 调用替换为合成桩；真实地址发送和复制循环执行原指令。全部输出及边界保护字节通过。命令序列为 `03 + 三字节地址`。另执行原 getter 确认128KiB逻辑长度。未运行更新/擦除函数，**未取得一个真实设备字节**。

身份数据还被 `0x1ef3e8` 的 PCM 上下文初始化使用；这是 EXS/机器绑定分析的候选线索，尚未证明具体密钥派生，更未证明能借此读取 TG ROM。直接 BL 调用关系已保存，但不覆盖全部间接分发。

此前已确认的 TG 原机采样目标仍是下64MiB；启动 SPI 与 USB 系统卷是不同后端。目前最值得继续的是诊断/MIDI命令分发是否能到达 TG 只读函数，以及缺失的128KiB启动代码能否只读取得。不能通过向 USB 盘放入 `BOOTSYS.BIN` / `KROSSPCM.BIN` 获得导出；当前代码显示它们用于更新。
