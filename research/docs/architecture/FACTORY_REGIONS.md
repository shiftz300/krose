# 原厂素材如何组成左右声道与键区

KROSS 2 v1.2.4 · 阶段 03 · 2026-11-01

固件会从素材名称建立立体声目录，再为每个 Multisample 生成 128 项音符映射。原 ARM 遍历确认：板载旋律素材有 7 对立体声，左右有效键区一致，没有出现上一轮合成实验中的单侧键区缺失。

## 1 立体声目录由固件生成

`0x283E04` 查找名称末尾的 `-L`，把末尾改成 `-R` 后搜索另一侧，生成含两个素材编号的记录。搜索先向后、再向前。`0x28543C` 根据侧别返回对应编号；OSC 刷新入口 `0x1F6654` 分别装载两侧。

本轮直接运行目录构造函数，得到的顺序与此前按名称推断的结果一致：

| 立体声编号 | 名称 | 左 / 右 Multisample |
| --- | --- | --- |
| 0 | KROSS Piano-mp | 0 / 1 |
| 1 | KROSS Piano-mf | 2 / 3 |
| 2 | KROSS Piano-f | 4 / 5 |
| 3 | Piano Damper | 6 / 7 |
| 4 | Acoustic Piano | 8 / 9 |
| 5 | Brass Ens 4 | 170 / 171 |
| 6 | Str.Ensemble 2 | 200 / 201 |

所有七对在查询音符 0–120 上都有有效区域；121–127 两侧同时为空。这里的音符是**区域查询输入**。实际按键还会经过移调、音高计算等步骤，因此不能直接据此判断最高几个 MIDI 音符的最终发声行为。

## 2 区域映射与 Program 引用

`0x1F5928` 按区域的上界音符填充映射。每项保存区域内索引；最后一个上界之后填 `-1`。`0x1F5B24` 将该索引与 Multisample 的首区域编号相加，找到 20 字节区域记录。

496 个普通 Multisample、每个 128 音符，共 **63,488 次**原区域查找通过。3,311 项映射为空；所有有效映射引用的采样编号都在板载 4,068 个音乐采样内。

随后对原厂 726 个旋律 Program 的 1,315 个活跃 OSC 执行素材刷新，核对了 2,445 个有效描述符侧别。原函数生成的左右素材指针与 128 项映射均一致。此处检查素材引用完整性，力度选层与最终音高计算见其他章节。

## 3 一个需要保留的初始化细节

六个 SineWheel 素材的第一个区域上界为 0。映射函数仅在上界大于 0 时写入这一段，因此它们保留音符 0 的原映射字节。填入 `A5` 后执行原函数，该字节仍为 `A5`；以零初始化时保持 0。

涉及编号为 341、343、344、346、347、349。重建对象时应明确初始化映射，不能把这段函数误写成总会覆盖全部 128 项。原 OSC 对象的首次构造及异常重载行为仍需继续核对。

## 4 对配对残留问题的判断

[构造失败实验](VOICE_FAILURES.md)中的单侧缺项，在当前七对板载旋律素材中没有找到对应数据。这个结果缩小了后续排查范围：扩展银行、银行切换、装载失败与损坏素材仍待检查。当前证据不足以认定原厂预置会触发该问题。

后续[原厂真实声部链](FACTORY_VOICE_CHAIN.md)已把实际选层、区域/采样构造、分配和完整 TG 启动接入同一原调用，另执行原反向能力目录构造。原厂范围中点、交叉权重、非标准音高斜率与采样地址均有新增检查。
