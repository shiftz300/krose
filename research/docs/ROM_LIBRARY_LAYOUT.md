## 原机 PCM 目标范围：下64MiB

以下三条证据相互吻合：

1. 样本描述符的地址单位取决于 flags bit0。原搬移函数 `0x12b828` 对 byte offset 先右移一位，bit0=1时再左移回去。两种标志均已执行原 ARM 核对。这支持 bit0=1 按字节解释、bit0=0 按16bit单元解释地址；并不代表所有其余编码标志都已解开。
2. 经上述单位换算，全部4070条描述符都落在 `[0, 0x04000000)`。最高结束边界候选为67108842，接近64MiB尾部。存在重叠/共享，不能把各描述符长度相加当作镜像长度。
3. 原 PCM 版本尾标读取函数 `0x11cd00` 使用 word index `0xfffffc..0xffffff`，每项读取两路u16，共16字节；对应候选字节区间 `[0x03fffff0, 0x04000000)`。启动代码 `0x2b7124..0x2b7198` 随后检查 `KORG` 字样并显示版本。尾标读取也已用合成KORG/version字节执行原ARM核对。

扩展读取调用方 `0x1ed3cc` 将块号加 `0x100`；每块为256KiB，故这一路从候选64MiB之后开始。与下64MiB作为原机区域、后续区域承载扩展的解释一致，但未读取硬件，不将其当成物理芯片容量/完整分区表的最终证明。

当前应寻找的是**含原机下64MiB的PCM映像**，而不是把官方“128MB线性PCM等效”当成必须找到128MB原始文件。若恢复文件另有头、封装或多个分区，仍需确定payload基址。

## 完整块读取已执行核对

原函数 `0x11c90c` 在三种块号 `0`、`0xff`、`0x100` 下完整执行。底层读取全由合成数据桩替代；每块131072次u16读取、输出262144字节，序列、端序和全部输出与独立期望数据一致。对应下64MiB首块、末块及后续区域首块，检查的是地址边界与复制逻辑。

报告 `layout-check-arm.json` 包含8个getter、2个地址单位案例、诊断初始化、3个整块及1个尾标读取检查。**没有一个真实ROM音频字节由这些测试取得。** 固件已有读函数也不等于电脑可以通过标准USB/MIDI直接调用。

## USB内部存储线索

找到机主 dkb 的一手维修经历：[iFixit原帖](https://www.ifixit.com/Answers/View/886888/Korg+Kross+2+-+Pitches+reversed+or+not+sounding)、[同作者论坛后续](https://www.keyboardforums.com/threads/korg-kross-2-pitches-reversed-or-not-sounding.35989/)。他报告特定开机组合能把内部存储以USB磁盘呈现，拷入另一台琴的文件后修复系统数据，还导致系统版本回退。这两个页面来自同一作者，不算两次独立验证。

这支持“可取得内部系统文件备份”的实机路线，但来源没有给出PCM内容清单，**不能证明USB盘一定暴露TG PCM区域或含KROSSPCM.BIN**。后续用户已让自己的琴进入该模式，并在Mac终端取得完整USB设备镜像：131072000字节，设备标识KORG KROSS2，卷名KORG SYSTEM；两次源读取及独立本地哈希一致。备份位于 `research/libraries/KROSS2_local_20261101-022845/`，源设备已安全弹出。根目录50个文件中未见KROSSPCM.BIN或BOOTSYS.BIN；仍未据此声称取得TG PCM ROM。

本次主应用镜像有BOOTSYS.BIN的加载/更新引用，但没有取得实际BOOTSYS；USB存储模式可能属于未包含在更新包中的启动代码，仍待备份核实。不能因主应用中未找到普通USB-MSC签名就断言该模式不存在，也不能据社区经历直接写出已验证的原机导出教程。没有执行来源中的删除、修复、替换文件步骤。

固件中的 `Dump PCM Bank Information` / `Dump PCM Name Information` 分别有输出构造代码（命令族 `0x73`、子项 `0x14/0x15` 的线索）。目前只能确认这些是银行/名称信息输出，未确认可用它们导出原始音频；也没有发送试探性SysEx给键盘。
