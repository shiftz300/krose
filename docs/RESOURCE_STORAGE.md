# 资源体积复核

2026-11-04。原厂 TG ROM 是 **64 MiB**，这是用户提到的约 60 MB 的来源。当前插件还包含 EXPCM001／002／004，原始 KEP 分别为 45.28、8.72、8.12 MiB；这四份来源合计 126.12 MiB。插件运行包将原厂编码波形预先解码成 PCM24，因此不能直接拿它和单份 ROM 比较。

## 逐项核对

| 运行资源 | 体积 | 检查结果 |
| --- | ---: | --- |
| Factory.samples | 373.33 MiB | 4,920 条采样，全部被 region 引用；元数据约 6.56 MiB |
| SEGrand.samples | 97.93 MiB | 84 组立体声，168 条声道全部逐字节匹配 Factory 内已有波形 |
| 原生界面资源目录 | 约 6.7 MiB | PNG、点阵字形和描述，不是体积大头 |

Factory 内部另有约 0.45 MiB 完全相同的波形载荷，仅约 0.12%；这轮保留采样 ID、音高和区域描述，避免为了小幅收益改变运行格式。现有 bank 6 缺失仍是四条鼓组层，本次未填补或编造素材。

## 已修复

1. **安装两份完整采样**：独立程序与 VST3 原本各带一份约 471 MiB 的采样。安装版改用单一、按产品版本区分的共享采样目录。便携版继续保留内置采样。
2. **CI 资源重复波形**：归档只保存 Factory 和 Concert 引用索引。CI 重组声道，生成与原文件 SHA-256 完全一致的 Concert 包。
3. **压缩器**：原来使用 gzip level 1。改为可逆的三字节差分过滤与 XZ。代表性 15.50 MiB PCM 探针里，gzip 1/9 为 14.87/14.84 MiB，仅提升级别几乎无效；差分 XZ 为 13.34 MiB。最终数值按整个归档实测，不用小样本外推。

| 实际产物 | 之前 | 现在 |
| --- | ---: | ---: |
| CI 完整资源归档 | 426.53 MiB | **286.60 MiB** |
| macOS arm64 安装包 | 约 868 MiB | **442.86 MiB** |
| 安装后的采样副本数（app + VST3） | 2 | **1** |

CI 归档与最终安装包用途不同，不能将两者体积互相代替。当前 PKG 仍包含两种运行采样布局各一份：Factory 的单声道库与 Concert 的交错立体声库。它们已在 CI 传输归档去重，安装后的约 98 MiB Concert 重复尚未从运行格式中消除。

## 进一步缩小的主要方向

当前最主要的剩余开销是**提前展开 PCM24**。若要接近原始来源的约百 MiB 量级，应把原厂压缩波形保留在磁盘，在现有加载线程按当前音色解码，并让 Concert 引用同一份原厂波形。该改动需要新的运行库格式、解码器和声音逐样本对照，普通 ZIP／gzip 参数无法代替。

本轮验证：重建后的两个运行包均与冻结清单哈希完全一致；共享采样目录的原生 VST3 通过全部音色、三种采样率、MIDI、状态恢复与 ARP 回归；便携构建的 11 项 CTest 通过。原始计数、来源哈希及日志见 [resources](verification/resources/)。完整采样与安装包尚未上传发布。
